# APIDemo

A Maven-based API test automation project for validating the public Zippopotam postal-code API. The suite verifies successful responses, error handling, edge cases, and JSON schema compliance using Java, TestNG, and RestAssured.

## Overview

This project exercises endpoints such as:

- `GET /{country}/{postalCode}`
- Example: `https://api.zippopotam.us/de/01067`

The tests validate that the API returns the expected country metadata, location details, and status codes for valid and invalid inputs.

## Tech Stack

- Java 25
- Maven
- TestNG
- RestAssured
- JSON Schema Validator

## Key Components

### `config/ConfigReader.java`
Loads application configuration from `src/main/resources/config.properties` and exposes the base URL for API calls.

### `constants/Endpoints.java`
Stores reusable endpoint definitions, including the postal-code route pattern.

### `restutils/RestHelpers.java`
Contains HTTP helpers built around RestAssured for GET requests and response extraction.

### `services/ZipCodeLocationService.java`
Acts as the service layer that wraps API requests for postal code lookups.

### `ZipCodeTest.java`
Contains the automated TestNG tests for positive, negative, and edge-case scenarios.

### `response-schema.json`
Defines the expected JSON structure for a valid Zippopotam response and is used for schema validation.

## Configuration

The base URL is configured in:

```properties

```

```properties
base.url=https://api.zippopotam.us
```

## Test Coverage

The suite includes checks for:

### Positive cases
- Valid country + valid postal code
- Multiple place results
- Country code case-insensitivity
- Correct response body details

### Negative cases
- Non-existent postal code
- Invalid country code
- Country/postal code mismatch

### Edge and contract validation
- Special characters in path parameters
- Response schema validation
- Status code assertions

## Running the Tests

From the project root, run:

```bash
mvn test
```

This command compiles the project and executes the TestNG suite configured in `testng.xml`.

## Notes

- The project validates the public Zippopotam API rather than a local backend.
- Tests are designed to confirm both business behavior and API contract stability.
- Generated build artifacts are stored under the `target/` directory.
